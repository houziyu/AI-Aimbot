# 准星助手使用教程

## 1. 安装与启动

在项目根目录执行：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main_ui.py
```

无需执行 `Activate.ps1`，不会受 PowerShell 脚本执行策略影响。后续双击项目根目录的 `start_ui.bat` 即可。

项目仅保留桌面版主程序和 ESP32 方向测试脚本，所有辅助参数在界面中配置。方向测试结束后先退出脚本，再连接桌面版，避免竞争串口。

## 2. 先确认硬件链路

ESP32-S3 XY1 固件支持双轴可变位移，源码与恢复步骤见 `firmware/esp32_xy/README.md`。电脑端会自动识别 XY1，也兼容旧版方向固件。

1. 用 USB 数据线连接 ESP32，在设备管理器或控制台下拉框中找到 COM 口。
2. 打开 Windows 蓝牙设置，确认 `ESP Mouse` 已配对且连接。
3. 退出占用 COM 口的串口监视器。
4. 必要时用已有脚本单独测试方向：

```powershell
.\.venv\Scripts\python.exe esp32_ble_mouse.py --port COM7
```

将 `COM7` 替换为实际端口；输入 `right`、`left`、`up`、`down`，每次回车发送一次。输入 `exit` 退出并释放串口，再启动桌面版。

指令通过 USB 串口发送，光标通过蓝牙 HID 返回电脑。XY1 固件支持蓝牙状态查询；旧版方向固件的蓝牙连接需要在 Windows 设置中检查。

## 3. 控制台操作

### 连接与选择窗口

点击「刷新」，选择 COM 口，再点击「连接设备」。程序默认关闭辅助，不会因为连接成功直接移动光标。

打开目标程序后点击「刷新窗口」，选择要识别的窗口。截图以窗口**客户区中心**为中心，不包含标题栏；窗口移动后坐标会重新计算。截图边长不能大于客户区宽高，截图区域必须完整位于桌面范围内。

建议先在窗口化或无边框窗口中测试。截图为桌面像素，目标窗口必须位于前台；被其他浮层遮挡的内容也会进入截图。受保护的画面或部分独占全屏模式可能出现黑屏，此时换用窗口化模式。

### 开启与关闭

**不接设备先验证识别**：选择目标窗口后点击「仅识别预览」，再切回目标窗口。截图、检测框和性能统计照常更新，但不会发送位移。预览与辅助互斥，先停止预览再开启辅助；预览期间右键/Caps Lock 不会把它切换为辅助输出。

| 操作 | 结果 |
| --- | --- |
| 界面「开启辅助 / 关闭辅助」 | 切换辅助状态，开启需要连接设备 |
| 界面「仅识别预览 / 停止预览」 | 无需设备，只检查截图与识别 |
| 在其他程序中按一次右键 | 默认禁用；启用右键快捷键后切换辅助状态，长按不会反复切换 |
| 在其他程序中按一次 Caps Lock | 默认启用；启用时切换辅助状态 |
| F8 | 停止辅助与预览，不会重新开启 |
| 目标窗口离开前台 / 最小化 | 保持开启状态，暂停截图和发送，切回后恢复 |
| USB 串口拔出 | 约 1 秒内检测到并关闭辅助；不自动重连 |
| 目标窗口尺寸过小 / 截图区域超出桌面 | 暂停等待，放大或移回窗口后恢复；也可先停止再修改截图尺寸 |
| 目标窗口关闭 | 停止识别，保留设备连接；刷新并重新选择窗口 |
| 截图或模型加载 / 推理失败 | 停止识别，保留设备连接；修正后重新开启 |
| XY 固件报告蓝牙断开 | 关闭辅助并保留串口；蓝牙恢复后需手动开启辅助 |
| 仅识别预览时串口异常或手动断开设备 | 预览继续，设备状态和日志更新 |
| 关闭助手窗口 | 停止新输出，等待后台释放设备后退出 |

在助手自身窗口内，右键/Caps Lock 不切换状态；用界面按钮控制。快捷键不会吞掉原始输入，因此右键仍可触发目标程序原本的功能。软件不根据 Caps Lock 指示灯判断辅助状态。

关闭辅助后，在「参数设置 → 辅助快捷键」分别勾选或取消鼠标右键、Caps Lock，点击「保存并应用」。配置会保存到本机，控制台显示各快捷键的启用状态。两个快捷键都关闭时可以用界面按钮控制，F8 始终可用。旧配置缺少快捷键字段时，默认关闭右键、开启 Caps Lock。

右键用于开镜时，建议关闭右键快捷键。换弹导致游戏自动收镜后，再按右键开镜就能保持辅助的原有状态，辅助由 Caps Lock 手动切换。

关闭立即作废正在推理和等待发送的结果。设备线程处理完已经开始的写入后，清理串口待发缓冲并向 XY1 固件发送停止标记。已经进入串口或蓝牙链路的单条位移仍可能到达 Windows。

主状态会明确显示「加载模型」「等待窗口」「正在识别」「仅识别预览」「等待蓝牙」及对应错误。参数设置中可以启用「开启、停止或异常时播放提示音」，默认关闭；提示音遵循系统声音设置。

### 观察预览和性能

开启后切回目标窗口，后台每秒最多更新 10 次预览；识别频率上限单独为 30/60/120。预览有检测框、置信度、准星中心、选取半径和所选目标瞄准点。

回到助手前台后截图会暂停并清空预览。需要一边观察一边测试时，将助手放在目标窗口旁边或另一块屏幕，保持目标窗口处于前台。不要让助手预览覆盖目标截图区域。

- **实际识别频率 / 串口写入频率**显示最近 1 秒实际完成的识别次数和写入条数。预览模式写入频率为 0。
- **截图耗时**：最近一帧截图及转换为图像数组的时间。
- **单轮识别耗时**：预处理、模型推理、筛选与目标选择总时间，不含截图与预览绘制。
- **串口写入耗时**：最近一次发送的本机写入耗时，尚未发送时显示「—」。
- **设备回执等待**：最近一次 XY 位移指令从请求到电脑处理回执的时间，包含电脑轮询间隔；旧固件和未收到位移回执时显示「—」。
- **画面处理耗时中位 / P95**：最近最多 120 帧从开始截图到目标筛选完成的统计。P95 表示约 95% 的样本耗时不超过此值，用于观察偶发卡顿；不含设备通信。
- **写入时画面年龄 / 电脑端过期**显示最近一次写入前距开始截图的时间，以及电脑端因超出有效期而丢弃的位移结果数。
- **串口写入 / 固件接受 / 拒绝 / 未确认**分别统计写入成功的指令、XY1 固件接受或拒绝的指令，以及尚无有效回执的指令。拒绝中标出过期和忙碌，未确认中标出回执超时。停止后保留本次计数，下次开启辅助或预览时重置。
- **指令到达 Windows**：未测量。XY1 回执确认报告交给蓝牙栈，Windows 实际消费报告的时间需另外测量。

## 4. 参数调整

先停止辅助与预览，进入「参数设置」，修改后点击「保存并应用」。仅编辑控件但没有保存，不会改变正在使用的参数。控制台频率按钮在辅助与预览关闭时可以直接保存频率。

### 保存和恢复参数方案

1. 调整表单参数，输入名称，点击「保存 / 覆盖方案」。同名会覆盖；这一步只保存方案，不改变当前应用参数。
2. 「复制当前参数」把当前表单保存为一个名称不重复的副本。
3. 选中方案后点击「载入方案」，核对表单，再点击页面底部「保存并应用」。方案包括识别频率、模型、快捷键等设置，不绑定串口或窗口。
4. 「载入默认参数」只更新表单，点击「保存并应用」后生效，已有方案保留。
5. 「撤销上次应用」直接恢复并保存本次程序会话中上一次应用前的配置；只支持一步撤销，重启后撤销记录不保留。保存失败会回滚运行配置。

方案保存在 `%LOCALAPPDATA%\AimAssist\profiles.json`。无法读取的方案文件会保留并报错，不会被新方案覆盖。

| 参数 | 默认值 | 调整方法 |
| --- | --- | --- |
| 模型 | YOLOv5s 320 Half | 先验证默认模型，需要时再选 YOLOv5m |
| 计算设备 | CPU | GPU 运行库安装正确后下拉框才可选择 |
| CPU 推理线程数 | 自动 | 使用 ONNX Runtime 默认值，也可手动指定。可在相同窗口下对比实际识别频率和 P95，再决定是否保存 |
| 截图边长 | 320 px | 越大覆盖范围越大；模型输入保持其声明尺寸 |
| 识别频率上限 | 60 次/秒 | CPU 占用高时可设 30 |
| 位移发送上限 | 60 条/秒 | XY1 按上限发送双轴位移，实际速度受识别频率、回执和蓝牙链路影响；旧版方向固件在接近目标时降至 30 |
| 结果有效期 | 100 ms | 可设 20–500 ms，从开始截图计时。XY1 指令最多使用剩余时间与 80 ms 中的较小值 |
| 置信度 | 0.40 | 误检多时提高，漏检时适当降低 |
| 移动倍率 | 0.40 | XY1 中将画面误差换算为鼠标位移；增大可加快修正，过大可能越过目标 |
| 瞄准高度 | 0.30 | 从框顶部开始的比例；0.12 接近头部，0.30 上身，0.50 中心 |
| 选取半径 | 140 px | 人物框与选取圆相交时参与选择，近距离大人物的瞄准点可在圆外 |
| 死区 | 12 px | 任一轴误差小于该值时停止该轴修正；抖动时可增大 |
| 修正值上限 | 40 | XY1 每条指令的单轴最大位移 counts，两个轴可同时发送 |
| 底部遮罩 | 关闭 | 可遮挡左下或右下角，减少手持物或人物自身干扰 |

XY1 支持双轴和可变步长，小误差可执行 1 count 修正。旧版方向固件使用固定步长，不同倍率可能表现相同。

XY1 的倍率以 60 次/秒为基准，发送线程按实际发送间隔换算位移，降低 30/60/120 识别频率切换造成的速度变化。每条指令仍受「修正值上限」限制，达到上限时低发送频率不能保持同样的最大速度。最多按 33.3 ms 换算，长于 100 ms 的停顿重新起步；停止、换目标和死区不积攒位移。此换算不改变旧方向固件的固定步长行为。

识别与串口通信在独立线程中运行。识别完成会唤醒设备线程，待发送区只保留最新结果，每帧最多尝试一次位移。XY1 在固件端继续检查同一帧的有效期。旧版方向固件仅支持电脑端写入前检查。

目标保持结合人物框大小、短时运动方向、位置和重叠率。新目标明显更近时，需要连续至少 3 帧且持续 100 ms 才切换；原目标无法匹配时，新目标需要至少 3 帧且持续 50 ms 确认。漏检期间不发送位移，目标记录按观测间隔保留 50–150 ms，随后清除。仅凭框的位置与大小不能保证多人遮挡后身份始终一致。

性能监测中的「模型推理耗时」仅统计模型执行；下方另外显示预处理、后处理、目标筛选和等待发送时间。P50/P95 仍统计从截图开始到目标筛选完成，最多每秒汇总 5 次；普通界面每秒刷新 10 次，快捷键每 20 ms 检查。

## 5. 模型与 GPU

支持输入为 `[1, 3, H, W]`（可有动态 H/W）的单输入 ONNX，类型 float16 或 float32。输出要求为 YOLOv5 原始 `[1, N, 5 + 类别数]`，类别 0 为人物。YOLOv8 转置输出、内置 NMS 的模型或其他类别顺序不在支持范围内。

默认依赖安装 CPU 版 ONNX Runtime。GPU 请在独立环境中按 [ONNX Runtime 官方安装说明](https://onnxruntime.ai/docs/install/) 安装对应版本；一个环境中只保留一种 ONNX Runtime 发行包，避免 CPU、DirectML、CUDA 包覆盖同名模块。不要在运行中的程序里更换包。

DirectML 使用对应 `onnxruntime-directml` 发行包；CUDA 使用 `onnxruntime-gpu`，还需满足其 CUDA/cuDNN 依赖。重新打开程序后检查下拉框。程序拒绝不可用的计算设备，并在加载失败时记录错误。界面显示的是所选执行提供程序，不代表所有节点都一定在 GPU 上执行。

已安装多个计算后端时，可以运行 `.\.venv\Scripts\python.exe tools/benchmark_backends.py --output artifacts/backend-benchmark.json`。工具对同一张本地样例预热后执行 3 轮、每轮 60 次检测，报告 P50/P95、各阶段耗时及进程 CPU 时间，并检查检测结果与 CPU 是否接近。初始化失败或输出不一致的后端不会被推荐；只生成报告，不修改已保存参数。建议在目标程序运行时再次测量，再在设置页选择计算设备。

Apex 图片与视频测试的复现命令、样例来源及已观察到的漏检，见 [Apex 验证记录](Apex验证记录.md)。

## 6. 常见问题

| 现象 | 排查方法 |
| --- | --- |
| 双击提示未安装 | 按第 1 节创建 `.venv` 并安装桌面依赖 |
| `No module named ...` | 使用 `.venv\Scripts\python.exe`，重新执行桌面依赖安装 |
| 没有 COM 口 | 检查数据线、USB 连接和设备驱动，然后刷新 |
| 串口拒绝访问 / Access denied | 关闭串口监视器和另一个辅助进程 |
| 串口已连接但不动 | 检查蓝牙，再用方向测试脚本验证；检查辅助开关、目标窗口是否前台 |
| 一直等待目标窗口 | 选择正确窗口并切回；目标重新启动后刷新重选 |
| 没有检测框 | 检查画面中是否有人形、置信度、遮罩和模型；通用模型可能不适合特定画风 |
| 检测到但不发送 | 人物框需与选取圆相交，误差需超过死区和协议量化阈值 |
| 来回摆动或对不准 | 增大死区；固定步长、系统鼠标设置和目标程序灵敏度都会影响结果 |
| 画面黑屏 | 尝试窗口化/无边框，确认目标不受截图保护 |
| GPU 不可选 | 当前环境未安装对应执行提供程序；先用 CPU 验证 |
| 模型格式错误 | 使用自带模型；不要选 `.engine`、`.pt` 或 YOLOv8 输出格式 |
| 配置损坏 | 程序使用默认值并记录错误，原文件保留；备份后修正或在界面重新保存 |
| 退出暂时等待 | 推理/模型加载不能中途强杀；界面先停输出，再等后台释放串口 |

日志页可点击「打开日志文件夹」，完整异常堆栈位于 `%LOCALAPPDATA%\AimAssist\runtime.log`。

## 7. 验证范围

自动测试验证预处理与坐标还原、置信度筛选/NMS、目标保持与丢失、参数校验、串口协议与限速、在途推理取消、断开连接和前台暂停。UI 渲染工具不会连接设备或移动光标。

最终硬件验证需要按「方向测试 → 连接 UI → 选窗口 → 查看识别 → 开关测试 → 断开测试」完成。开发检查不能代替实际 ESP32 蓝牙链路和目标程序内的操作体验。

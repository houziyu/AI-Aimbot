# 开发验证记录

最新验证日期：2026-11-13。

## 2026-11-13 五项优化与 Apex 素材验证

- `pytest tests -q`：**92 项通过**。新增不同识别/发送频率下的累计位移、控制器与发送换算组合回放、停顿与饱和、不匹配目标确认、交叉移动、持续切换优势、百分位统计不持锁、过期统计丢弃、界面刷新节流下 F8 生效及测速失败/结果不一致的覆盖。
- UI 离屏渲染通过并检查完整控制台，模型推理与其余阶段已分开显示。普通显示 10 Hz、快捷键轮询 50 Hz；P50/P95 5 Hz 在锁外计算。
- 后端测速：默认模型，320 样例，预热 10 次、3 × 60 次采样。CPU P50/P95 **18.94 / 20.53 ms**，DirectML **6.35 / 6.90 ms**；该样例上的检测结果一致。这是检测调用耗时，不含截图、串口或蓝牙。
- 真实截图 + 模拟 XY1，识别上限 120：CPU 一次样例约 43 次/秒，画面处理 P95 25.92 ms；DirectML 采样 10 秒，末次统计约 77 次/秒，最近 120 帧 P95 17.24 ms。两者均停止后无新位移。该运行有系统调度及截图抖动，不能等同于模型裸测速。
- DirectML 无设备预览与 CPU 旧协议联调均通过，停止后没有输出、退出后两工作线程结束。
- Apex：8 张公开图片（5 张官方宣传图、3 张第一人称交战图）与一段 94.6 秒的官方 1080p/30 fps 视频，分别检查 s/m 两套模型。视频每套处理 **2,837 帧**，结果与边界见 [Apex 验证记录](Apex验证记录.md)。原始素材仅保存在忽略的 `artifacts/`，仓库保存来源、SHA256、复现工具和文字报告。
- 本轮未向真实 ESP32 发送位移，未运行 Apex 客户端，未测量真实 HID 接收或实战手感。玩家素材里存在明显未检出场景，当前结果不能称为 Apex 专用模型验证通过。

## 2026-11-13 位移时效、停止与 CPU 线程

- `pytest tests -q` 共 **72 项通过**，覆盖从截图传递到 XY1 的截止时间、32 位时钟回绕、停止时丢弃残帧、晚到回执、串口写入阻塞时 F8 作废待发结果，以及写入与回执分别计数。
- `tools/check_ui.py` 完成控制台、参数设置、运行记录和小窗口的离屏渲染。真实截图与 ONNX 模型联调通过，仅识别预览未打开串口，模拟 XY1 与旧版串口均通过停止后无新位移的检查。
- 本机用默认模型、120 次/秒上限和相同样例窗口，在预览出现后采样约 3 秒。自动线程两次的画面处理 P95 为 25.4 和 26.3 ms，识别约 43–44 次/秒。8 线程两次的 P95 为 24.3 和 24.5 ms，识别约 42 次/秒。设置页提供线程数选项，默认使用 ONNX Runtime 自动配置。
- COM3 的现有 XY1 固件完成握手，停止标记返回 `STATUS`。把有效期为 35 ms 的零位移指令延迟 70 ms 后写入，板端返回 `EXPIRED`。实机验证未发送非零位移，也未测量 Windows HID 接收延迟。

- `tools/check_ui.py`：控制台、参数设置、日志、页面底部及 940 × 720 小窗口渲染并检查，截图位于 `artifacts/`。
- `tools/check_pipeline.py --simulate-focus`：真实 Win32 客户区坐标、MSS 截图、自带 ONNX 模型，以及模拟 XY1 固件的真实握手/CRC/回执解析通过。一次最终样例观测约 42 次/秒识别、42 条/秒发送，画面处理耗时中位约 22.7 ms、P95 约 27.1 ms；只代表本次本机样例，不能据此承诺实际设备性能。
- `tools/check_pipeline.py --simulate-focus --preview-only`：未调用串口打开函数，检测到人物，位移发送为 0，停止后无输出。
- `tools/check_pipeline.py --simulate-focus --protocol legacy`：兼容旧方向协议，检测、模拟输出和停止检查通过。
- 三种联调都确认退出时识别线程与设备线程结束。所有发送都指向模拟设备，没有操作真实 ESP32 或移动光标。

本轮仍使用模拟前台焦点完成自动截图联调。模型推理、截图和串口封包是真实实现，但设备回执由模拟器生成；显示的回执等待包含本机调度时间，不能代表真实蓝牙或 Windows HID 接收延迟。未新增 GPU、实机蓝牙、人工切换窗口和提示音实际听感验证。

## 2026-11-12 历史验证

以下为此前版本的记录，其中测试数量和固件能力不代表当前版本。

## 已执行

- Windows / Python 3.13 虚拟环境安装 `requirements.txt`，`pip check` 通过。
- `pytest tests -q`：15 项测试通过。涵盖坐标变换、NMS、目标保持/丢失、配置保存与校验、协议限速、在途推理取消、串口断开、设备拔出、截图异常、写入异常、窗口失焦暂停，以及 UI 导航、保存与快捷键边沿。
- 两个自带的 ONNX 半精度模型均在 CPU 上加载并完成推理。
- 从仓库自带的 Rust 样例图中取得人物检测结果。
- `tools/check_ui.py`：实际 Qt 控制台、参数页、日志页和小窗口截图检查通过。离屏渲染显式加载 Windows 中文字体。
- `tools/check_pipeline.py --simulate-focus`：临时显示仓库样例图，使用真实 Win32 客户区坐标、真实 MSS 截图和真实 ONNX 推理，输出到模拟串口。取得 1 个检测目标，并产生方向字节；关闭后不再输出，工作线程正常退出。

截图链路单次观测约 29 次/秒、识别约 21 ms。这只是本机一次样例检查，不是实际应用性能承诺。

## 未验证部分

- 自动启动的测试窗口未能取得 Windows 前台焦点，正常模式检查因此进入「等待目标窗口」；截图链路检查使用了 `--simulate-focus`。前台保护逻辑另有单元测试，真实用户切换窗口仍需在桌面上验证。
- 本轮没有向真实 ESP32 发送位移。真实蓝牙 HID 接收、方向步长、目标程序灵敏度和最终手感需要用户连接现有设备验证。
- 未安装和运行 DirectML / CUDA 后端。
- 固件无 HID 接收回执，无法验证端到端延迟或独立蓝牙断连检测。

## 复现

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe tools/check_ui.py
.\.venv\Scripts\python.exe tools/check_pipeline.py
```

最后一条会短暂打开测试窗口，模拟串口输出，不移动真实光标。应保持测试窗口前台；无法获得焦点的自动化环境可加 `--simulate-focus`，此参数只修改测试脚本的模拟行为，不修改主程序的前台保护。
